# Cypher и SQL

## Осмотрите граф перед запросами

```sh
khonsu schema --db graphs/demo
```

Результат перечисляет метки, типы связей, имена свойств, количества, шаблоны связей и таблицы SQL. Используйте эти имена, а не схему другого графа.

## Возвращайте связи

```cypher
MATCH (a:Host)-[r:DEPENDS_ON]->(b:Host)
RETURN a, r, b
LIMIT 20
```

Если возвращать узлы и связи целиком, в результат попадают и значения таблицы, и элементы графа. Возврат только `a.name` даёт скалярный столбец, а не связный граф. В CLI элементы графа попадают в отдельный объект `graph`.

Cypher поддерживает `MATCH`, `OPTIONAL MATCH`, `WHERE`, `RETURN [DISTINCT]`, `ORDER BY`, `SKIP`, `LIMIT`, `WITH`, `UNWIND`, `CASE` и шаблоны переменной длины с ограничением. С `--write` доступны также `CREATE`, `MERGE`, `SET`, `DELETE` и `DETACH DELETE`. Например, для графа сервисов:

```cypher
MATCH (a:Service)-[:CALLS*1..4]->(b:Service)
RETURN a, b
LIMIT 50
```

Так вы получите конечные точки. Чтобы нарисовать промежуточные связи, запросите связи с одним переходом отдельно.

## Кратчайшие пути

```cypher
MATCH p = shortestPath((a:Host {name: 'web'})-[:CALLS*..6]->(b:Host {name: 'db'}))
RETURN p, length(p) AS hops
```

Также работают `allShortestPaths`, `nodes(p)` и `relationships(p)`. Обе конечные точки должны быть заданы через карту свойств, `WHERE` или более раннюю конструкцию. Возврат `p` рисует путь на холсте. `*` без ограничения останавливается на 256 переходах и завершается ошибкой, а не сообщает об отсутствии пути.

Чтобы обойти граф от узла с ограничениями по числу переходов и размеру, используйте [`khonsu graph explore`](./investigations#explore). О взвешенных путях, центральности и сообществах см. [анализ графов](./analysis).

## SQL и параметры

Запросы SQL работают с таблицами в том же каталоге HawDB и используют SQL в диалекте PostgreSQL. Импорт графа не создаёт таблицу SQL с тем же именем. Сначала проверьте `schema`. В следующем примере нужна таблица `assets`:

```sh
khonsu query --db graphs/demo --sql "SELECT * FROM assets LIMIT 20"
khonsu query --db graphs/demo --cypher \
  'MATCH (h:Host) WHERE h.name = $name RETURN h' -p name=web-01
```

Значения `-p` разбираются как JSON, если это возможно, иначе как строки. В SQL используются позиционные параметры (`$1` вместе с `-p 1=value`).

## Текущие ограничения {#current-limitations}

KhonsuGraph 0.3.0 использует HawDB 0.29.0, где Cypher отличается от других графовых баз данных:

- `labels()`, `keys()`, `properties()`, `CALL db.*` и `SHOW` не поддерживаются. Для метаданных используйте `khonsu schema`.
- Поддерживаемые агрегаты — `count`, `sum`, `collect`, `min`, `max` и `avg`, в том числе по выражениям.
- Запрос на чтение начинается с `MATCH` или `UNWIND`. `RETURN 1` сам по себе не разбирается, а `OPTIONAL MATCH` не может быть первой конструкцией.
- Шаблоны переменной длины требуют типа связи и не допускают переменную связи. Шаблон связи без типа работает только для одного перехода.
- Переменные пути работают только в `shortestPath` и `allShortestPaths`.
- Строки нельзя соединять через `+`, а `toLower`, `toUpper`, `reduce`, `any`, `all`, `none` и `exists` недоступны.
- `CREATE` принимает один шаблон на инструкцию. `LOAD CSV` отключён; загружайте файлы через [источник данных](./data-sources).
- Поддерживаются скалярный `IN`, списочные включения, `json_value()` для текста JSON, даты и длительности, а также `SET` для свойств связи.
- У запросов на чтение есть потолок в 100 000 строк. `--max-rows` ограничивает только отображаемые строки после выполнения, поэтому задавайте `LIMIT` и в самом запросе.
- Векторные значения возвращаются как массивы чисел JSON. Столбцы возвращаются в порядке `RETURN`; всё равно читайте их по имени.
- `WHERE true` работает в Cypher, но не в SQL.

Граф, записанный до HawDB 0.25, то есть в KhonsuGraph 0.2.0 или более ранней версии, эта версия прочитать не может; см. [устранение неполадок](./troubleshooting#old-format).

## Проверка запроса и вопросы словами онтологии {#semantic}

`--validate-only` проверяет Cypher-запрос по меткам, типам связей и шаблонам графа и ничего не выполняет: метка с опечаткой, связь, пройденная в обратную сторону, или шаблон, которого нет в графе, сообщаются вместе с похожими именами. `--semantic` позволяет называть в запросе понятия вроде `Device` и `Account` вместо меток конкретного источника. Обе возможности появятся в выпуске после 0.3.0; см. [онтологию](./ontology#semantic).

## Доступ на чтение и запись

Запросы CLI по умолчанию доступны только для чтения. `--write` явно включает запись. Каталог графа в каждый момент принадлежит одному процессу. Пока приложение держит граф открытым, запросы CLI на чтение и проверки дашбордов идут через это окно. Для записи и синхронизации граф должен быть закрыт в приложении.

Запрос, выполненный с `--write`, не входит ни в один источник данных, поэтому `khonsu graph rebuild` его не переносит. Начиная с выпуска после 0.3.0 каждый такой запрос записывается в `writes.jsonl` в папке настроек (когда, какой граф, запрос со скрытыми ключевыми данными и агент, который его выполнил), чтобы его можно было найти и выполнить снова.
