# Источники данных

Плагины превращают внешнюю систему в узлы и связи. KhonsuGraph запускает плагин отдельным процессом и записывает записи в граф.

## CSV

Встроенный плагин CSV сопоставляет строки узлам и связям. Выберите столбцы со стабильным ID, источником и целью; остальные столбцы становятся свойствами. Числовые и логические значения по умолчанию распознаются автоматически. Укажите `infer_types=false`, чтобы оставить текст.

Полный пример импорта см. в разделе [начало работы](./getting-started). Если в данных несколько меток узлов или типов связей, используйте конфигурацию JSON в полях `nodes` и `edges`. Пути внутри этого JSON должны быть абсолютными: плагин запускается из собственной папки, и автоматически в абсолютные преобразуются только поля для отдельных файлов.

```sh
khonsu plugin describe csv
khonsu source add --db graphs/demo --plugin csv --name mixed \
  -c 'nodes=[{"path":"'"$PWD"'/nodes.csv","label_column":"label","id_column":"id"}]' \
  -c 'edges=[{"path":"'"$PWD"'/edges.csv","type_column":"type","source_column":"source","target_column":"target","id_column":"id"}]'
```

## AWS

Плагин AWS использует AWS CLI, чтобы прочитать VPC, подсети, группы безопасности, инстансы, балансировщики нагрузки и роли IAM. Сначала установите и настройте AWS CLI, затем используйте профиль только для чтения, который вы контролируете. `regions` — список через запятую, например `us-east-1,eu-west-1`.

```sh
khonsu init graphs/aws
khonsu plugin describe aws
khonsu source add --db graphs/aws --plugin aws --name aws-demo \
  -c profile=readonly -c regions=us-east-1 --test
khonsu plugin sync --source aws-demo --dry-run
khonsu plugin sync --source aws-demo
```

Так вы обращаетесь к настроенному аккаунту AWS. Если нужен разбор без сетевого доступа, используйте сохранённые фикстуры в репозитории приложения; см. [примеры](./examples).

Дашборд <a href="/docs/samples/exposure.dash" download>открытости AWS</a> строит цепочку `Cidr → SecurityGroup ← Instance → Role` по связям, импортированным этим плагином.

## Neo4j и Cartography {#neo4j}

Плагин Neo4j, появившийся в 0.3.0, копирует узлы и связи базы Neo4j в локальный граф через HTTP API Neo4j. Он отправляет только запросы на чтение. Основной сценарий — [Cartography](https://github.com/cartography-cncf/cartography), которая собирает данные AWS, GCP, Azure, Kubernetes, GitHub, Okta и других систем в Neo4j; подойдёт любая база Neo4j.

```sh
khonsu init graphs/infra
khonsu source add --db graphs/infra --plugin neo4j --name infra \
  -c url=http://127.0.0.1:7474 -c password=... --test
khonsu plugin sync --source infra
```

Адрес — HTTP-адрес Neo4j, по умолчанию 7474, а не `bolt://`. Пароль хранится в связке ключей системы, достаточно роли читателя.

В HawDB у узла одна метка, поэтому каждый узел получает одну из своих меток Neo4j — обычно самую редкую, — а все метки сохраняются в `neo4j_labels`. Если `MATCH (p:AWSPrincipal)` ничего не возвращает, попробуйте `MATCH (p) WHERE 'AWSPrincipal' IN p.neo4j_labels`. Запросы, написанные для Neo4j, возможно, придётся изменить; см. [ограничения запросов](./queries#current-limitations) и [README плагина](https://github.com/JetSquirrel/KhonsuGraph/tree/main/plugins/neo4j).

## Семантика синхронизации {#sync-semantics}

- Стабильные ID позволяют повторным импортам обновлять существующие записи.
- Полная синхронизация удаляет ранее импортированные записи этого источника, которых нет в новом результате.
- Инкрементальная синхронизация только добавляет или обновляет записи, если плагин её поддерживает. `--append` делает то же для любого источника: используйте его, когда файлы содержат только то, что появилось после последней синхронизации.
- Неизменившаяся запись не записывается повторно, поэтому `nodes_written` и `edges_written` в отчёте о синхронизации считают только изменения.
- Неудачная синхронизация может сохранить уже записанные записи. Следующая успешная синхронизация их согласует.
- Ребро с неизвестной концевой точкой пропускается и учитывается в `skipped_edges`.

Импортированные записи содержат `khonsu_id`, `khonsu_source`, `khonsu_plugin` и `khonsu_synced_at`; [доказательства](./investigations#evidence) считывают их обратно. Пока приложение держит граф открытым, `khonsu plugin sync` выполняется через окно: оно показывает прогресс и повторно запускает открытые дашборды. Для записи запросами граф должен быть закрыт в приложении.

## Другие системы

Устанавливайте плагин только после проверки его разрешений. Разрешения — это декларации, а не песочница операционной системы. Секретные поля конфигурации хранятся в связке ключей системы. См. [разработка плагинов](./plugins).
