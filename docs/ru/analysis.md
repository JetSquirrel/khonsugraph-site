# Анализ графов

Запрос Cypher отвечает на вопрос о заданных шаблонах. `khonsu graph analyze` отвечает на вопросы о форме графа: какой узел самый центральный, какие группы образуются, как связаны два узла. Вычисления идут в памяти и следуют определениям networkx, поэтому на одном и том же графе результаты совпадают с networkx.

```sh
khonsu graph analyze summary --db graphs/audit
khonsu graph analyze pagerank --db graphs/audit --type TRUSTS --top 10
khonsu graph analyze communities --db graphs/investigation
```

На незнакомом графе начните с `summary`.

## Алгоритмы

| Команда | На что отвечает | Параметры |
| --- | --- | --- |
| `summary` | Размер, плотность, компоненты, кластеризация, наибольшее ядро и диаметр | |
| `degree` | У каких узлов больше всего связей | `--top N` |
| `pagerank` | На какие узлы указывает остальной граф | `--alpha 0.85`, `--weight PROP` |
| `betweenness` | Какие узлы лежат на наибольшем числе кратчайших путей | `--sample K` |
| `closeness` | Какие узлы находятся ближе всего к остальным по числу переходов | `--undirected` |
| `components` | Какие части графа не связаны между собой | `--strong` |
| `communities` | Какие группы плотно связаны (Louvain) | `--resolution 1.0`, `--seed 42` |
| `clustering` | Как часто соседи узла связаны между собой | |
| `kcore` | Плотно связанное ядро графа | |
| `path` | Кратчайший путь между двумя узлами | `--from ID --to ID` |

`path` принимает числовые ID узлов: верните `id(n)` из запроса или прочитайте `_id` в результате.

## Выбор подграфа

По умолчанию алгоритм читает весь граф. Сузить его можно тремя способами:

```sh
khonsu graph analyze betweenness --db graphs/sre --label Service
khonsu graph analyze pagerank --db graphs/audit --type TRUSTS
khonsu graph analyze pagerank --db graphs/security \
  --cypher "MATCH (a:Process)-[r:SPAWNED]->(b:Process) RETURN a, r, b"
```

- `--label` оставляет узлы с этими метками и связи между ними.
- `--type` оставляет эти связи и, если не указан `--label`, только узлы, которые они соединяют.
- `--cypher` анализирует ровно те узлы и связи, которые запрос возвращает целиком.

Связи считаются направленными, если не указан `--undirected`. Кластеризация, ядра и сообщества всегда читают их в обе стороны. `--weight PROP` берёт числовое свойство связи как вес для PageRank или как длину для путей, посредничества и близости. Отсутствующее значение считается равным 1.

## Вывод

Каждый запуск печатает один объект JSON с полями `algorithm`, `graph` (прочитанный граф: `nodes`, `relationships`, `directed`, `weighted`), `load_ms`, `elapsed_ms` и `rows`.

Строки узлов имеют вид `{id, labels, name, <score>}` и идут от лучших к худшим с ограничением `--top`. `components` и `communities` возвращают группы с их `size` и первыми десятью `members`; у сообществ добавляется `modularity`. `path` возвращает `found`, `hops`, `length` и узлы пути.

Посредничество вычисляется точно до 5 000 узлов, а выше — по выборке из 500 источников. Если результат точный, `sampled_sources` равно null; сообщая результат по выборке, укажите это.

## Анализ или Cypher?

В Cypher есть `shortestPath` и `allShortestPaths` между двумя заданными узлами; см. [Cypher и SQL](./queries). Используйте `khonsu graph analyze path`, когда путь должен учитывать вес, а остальные алгоритмы — когда вопрос касается всего графа, а не одного шаблона. Чтобы обойти граф от узла с ограничениями по числу переходов и размеру, используйте [`khonsu graph explore`](./investigations#explore).
