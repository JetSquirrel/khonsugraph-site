# Маркетплейс

Маркетплейс перечисляет плагины по имени. Для каждого плагина в нём указаны версия, объявленные разрешения и по одному пакету на платформу с его SHA-256. KhonsuGraph читает маркетплейс из локальной папки, репозитория GitHub или по адресу HTTPS.

::: info В следующем выпуске
Маркетплейс появится в выпуске после 0.3.0. Начиная с него, вместе с приложением поставляется только плагин CSV. AWS и Neo4j, как и SQL и DuckLocal, устанавливаются из официального маркетплейса. В 0.3.0 плагины AWS и Neo4j ещё поставляются вместе с приложением.
:::

## Установка плагина {#install}

```sh
khonsu plugin search              # что предлагают маркетплейсы
khonsu plugin install aws --yes   # загрузить, проверить, установить и одобрить
khonsu plugin update              # обновить установленные плагины
```

В приложении **Add Data Source… → More Plugins…** показывает тот же список. Плагин, установленный или обновлённый там, переходит к окну одобрения, а затем к форме источника.

Если два маркетплейса перечисляют один и тот же ID, укажите нужный: `khonsu plugin install sql@official`. `khonsu plugin update --dry-run` только сообщает, что изменится.

## Официальные плагины {#official}

| Плагин | Что он читает |
| --- | --- |
| `sql` | Таблицы PostgreSQL, MySQL и SQLite, сопоставленные вручную или по первичным и внешним ключам |
| `ducklocal` | Таблицы Parquet, CSV, JSON и DuckDB, прочитанные через DuckLocal |
| `aws` | VPC, подсети, группы безопасности, инстансы, балансировщики нагрузки и роли IAM через AWS CLI в режиме только для чтения. Предлагает анализ открытости и шаблон `aws.exposure` |
| `neo4j` | База Neo4j, например заполненная Cartography, копируемая через её HTTP API |

Каждая установка начинается с маркетплейса `official`. Он раздаётся с `marketplace.khonsugraph.com` и собирается из репозитория [khonsugraph-marketplace](https://github.com/JetSquirrel/khonsugraph-marketplace), где лежат исходный код и README каждого плагина. Плагин CSV остаётся встроенным.

## Что проверяется {#checks}

- Пакет должен совпадать с SHA-256, указанным в маркетплейсе, и содержать указанные плагин и версию. Иначе ничего не устанавливается, а ранее установленное остаётся.
- Индексы и пакеты читаются только по HTTPS.
- Установка — это не одобрение. Плагин из маркетплейса нужно одобрить до запуска, а после обновления — снова. `--yes` одобряет на том же шаге.

Маркетплейс сообщает, где лежит пакет и какой у него хеш. Он не делает плагин безопасным. Перед одобрением проверьте объявленные разрешения: это декларации, а не песочница. См. [разработку плагинов](./plugins).

## Добавление маркетплейса {#add}

```sh
khonsu plugin marketplace add acme/khonsu-plugins   # owner/repo на GitHub
khonsu plugin marketplace add https://plugins.example.com  # любой адрес HTTPS
khonsu plugin marketplace add ~/work/team-plugins   # папка
khonsu plugin marketplace list
khonsu plugin marketplace remove team-plugins
```

`khonsu plugin marketplace remove official` отключает официальный маркетплейс, а `khonsu plugin marketplace restore` возвращает его.

## Публикация плагина {#publish}

```sh
khonsu plugin publish ./my-plugin --to ~/work/team-plugins
```

Команда упаковывает плагин в папку и вносит его в `marketplace.json` этой папки. Закоммитьте и отправьте папку или загрузите её на статический хостинг. Другие добавляют её один раз через `khonsu plugin marketplace add`, а затем устанавливают по имени. Повторная публикация той же версии заменяет пакет этой платформы, так что каждая платформа может публиковать свою сборку. См. [полный справочник по маркетплейсу](https://github.com/JetSquirrel/KhonsuGraph/blob/main/docs/marketplace.md).
