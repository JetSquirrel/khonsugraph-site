# トラブルシューティング

## khonsu が見つからない

アプリのタイトルバーにある **コマンドラインと AI**(ロボットのアイコン)を使用し、ターミナルを開き直してください。macOS では、アプリのバイナリを直接呼び出せます:

```sh
/Applications/KhonsuGraph.app/Contents/MacOS/khonsugraph --version
```

Windows では、`khonsu.exe` を展開したパッケージの残りのファイルと同じ場所に置き、そのディレクトリを PATH に追加するか、フルパスで呼び出してください。

## グラフがロックされている

1 つのプロセスが HawDB グラフディレクトリを所有します。読み取りとダッシュボードのチェックは実行中のウィンドウ経由でルーティングされますが、書き込みとソースの同期にはグラフが空いている必要があります。他のプロセスでグラフを閉じてください。リースを回避するために `khonsugraph.lock`、`owner.hawdb.lock`、データベースファイルを削除しないでください。

## グラフが old_format を報告する {#old-format}

HawDB 0.25 でストレージ形式が変わり、それより古いグラフは読み取れません。そのため、KhonsuGraph 0.2.0 以前に書き込まれたグラフは、kind `old_format` で開くのに失敗します。`khonsu rebuild --db DIR` はデータソースからグラフを作り直し、古いディレクトリを `DIR.hawdb-old` として隣に残します。同期ではなく手作業で書き込まれたものは引き継がれません。

## グラフパネルが空になる

名前だけではなく、ノードとリレーションシップを丸ごと返してください(`RETURN a, r, b`)。ダッシュボードが対象としているグラフを開いているか確認してください。`khonsu schema --db DIR` を使用し、クエリを直接実行して、ラベルと結果を確認してください。

## クエリまたはダッシュボードが失敗する

`khonsu check FILE --db DIR` を実行し、報告されたすべてのエラーを読んでください。プロットが存在しない列を参照している可能性があります。インポートしたデータセットが異なるラベルを使用している可能性もあります。一部の Cypher 機能はサポートされていません。[クエリの制限](./queries#current-limitations) を参照してください。

読み取りが予算を超える場合は、述語と `LIMIT` を使って絞り込んでください。`--max-rows` を下げるだけでは、実行コストは減りません。

## ソースが同期できない

`khonsu plugin describe ID` を実行し、設定フィールドを確認してください。パッケージ化されたプラグインが実行ファイルの隣に残っていることを確認してください。単一ファイル CSV のパスは、ソースの追加時に絶対パスとして保存されます。`nodes` と `edges` の JSON 内のパスは指定されたとおりに保存され、絶対パスでなければなりません。フィクスチャを使用する場合を除き、AWS には AWS CLI とアクセス可能な設定済みプロファイルが必要です。`regions` は JSON 配列ではなく、カンマ区切りのテキストで記述してください。

失敗した同期は、すでに書き込まれたレコードを残す可能性があります。原因を修正してから再度同期し、整合させてください。解決されていない端点については `skipped_edges` を調べてください。

## 問題を報告する

[GitHub issue](https://github.com/JetSquirrel/KhonsuGraph/issues) に、アプリのバージョン、オペレーティングシステム、実行したコマンド、エラーの種類を含めてください。再現手順からは認証情報とプライベートなグラフの値を削除してください。
