# KhonsuGraph website

The multilingual product website and documentation for [KhonsuGraph](https://github.com/JetSquirrel/KhonsuGraph), an open-source, local-first graph investigation workbench built for hunters. Built following the structure of `ducklocal-site` and `cloudbridge-site`. English is served from the root; Chinese, Japanese, Korean, French, German, Spanish, Brazilian Portuguese and Russian live under `/zh/`, `/ja/`, `/ko/`, `/fr/`, `/de/`, `/es/`, `/pt/` and `/ru/`.

| Path | Contents |
| --- | --- |
| `home/` | Static product pages for nine languages, shared CSS and brand illustrations |
| `scripts/generate-home.mjs` | Homepage template; generates HTML, Markdown and discovery files |
| `scripts/home-content.mjs` | Homepage copy for English, Chinese, Japanese, Korean, French, German, Spanish, Brazilian Portuguese and Russian |
| `scripts/story-content.mjs` | Brand narrative for each homepage language |
| `scripts/landing-content.mjs` | English landing pages (`/use-cases/…`, `/compare/…`), one search intent each |
| `docs/` | VitePress documentation with local search, nine locales and downloadable samples |
| `dist/site/` | Complete production output, generated by the build |
| `wrangler.jsonc` | Cloudflare Workers static-assets configuration |

## Local development

Requires Node.js 22 or newer.

```sh
npm --prefix docs ci
npm run generate
npm run dev               # product pages on http://127.0.0.1:4173
npm run dev:docs          # VitePress development server
```

Edit homepage copy in `scripts/home-content.mjs` (and per-language narrative in `scripts/story-content.mjs`), then run `npm run generate`. Edit presentation in `home/styles.css`. Homepage HTML is committed so it can be served directly. The homepage is static and requires no JavaScript.

## Build and preview everything

```sh
npm run build
npm run preview           # http://127.0.0.1:4173, includes /docs/
```

Stop the other server first if port 4173 is occupied, or set `PORT=4174`. The build checks VitePress links, then checks all generated HTML links, anchor targets and local assets. `npm run check` repeats those checks against the existing build.

The pages have no analytics, external fonts or third-party scripts. VitePress search runs locally. The homepage needs no framework or runtime dependencies.

The `hawdb-wasm-demo` project is a design and interaction reference only; the website does not embed or link to its online demo.

`home/assets/exploration-story.png` is the user-supplied four-panel illustration, preserved as the original bitmap. Four SVG viewports display its individual panels in the brand narrative. The page serves `exploration-story.webp`, a quality-90 WebP encoding of the same bitmap (about 180 KB instead of 1.8 MB).

`home/assets/hero-traces.png` is the custom hero illustration generated with the built-in ChatGPT image generation tool. The generation prompt is saved in `artifacts/hero-image-prompt.md`. The page serves `hero-traces.webp` and a 960 px `hero-traces-960.webp` for narrow screens; regenerate them with `cwebp -q 82 -m 6` (add `-resize 960 0` for the small one) after replacing the PNG.

`home/assets/og-card.jpg` is the 1200×630 link-preview image every page names in `og:image`. `node scripts/og-card.mjs` renders it from the hero illustration and the logo; it needs `rsvg-convert` and macOS `sips`, and runs by hand, not in the build.

## Search and sharing metadata

The homepage title, meta description and structured data (`WebSite`, `SoftwareApplication`, `FAQPage`) come from `metaTitle`, `metaDescription`, `steps` and `faq` in `scripts/home-content.mjs`. Documentation pages take their description from front matter; `docs/.vitepress/config.mts` adds canonical and language-alternate links, Open Graph and Twitter tags, and `TechArticle` and `BreadcrumbList` data. The sitemap repeats each page's language alternates. Headings that other pages link to carry explicit IDs (`## Title {#id}`) so anchors match in every language.

## Deployment

The site is served at `https://khonsugraph.com`. Canonical URLs, language alternates and absolute discovery links use that origin; override it with `SITE_URL` for another deployment:

```sh
SITE_URL=https://preview.example npm run build
```

The build writes `/sitemap.xml` from the canonical URL of every published page and adds its `Sitemap:` line to `robots.txt`, so adding or removing a page updates both on the next deploy.

For Cloudflare Workers Builds, use project name `khonsugraph-site` and deploy command `npx wrangler deploy`. The configuration runs `sh scripts/build.sh`, installs the locked docs dependencies, and serves `dist/site`. Domain binding is a separate hosting setup step.

Routing follows [Cloudflare's static HTML handling](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/): document routes resolve without `.html`, directory indexes retain trailing slashes, and unknown routes use a 404 page.

## Content provenance

Product content comes from the app README, PRD, agent skill and CLI reference, plugin protocol, investigation and snapshot docs, and examples, as of KhonsuGraph 0.3.0 (HawDB 0.29.0). Downloads link to the releases listing without assuming a release asset exists. The logo and `.dash` samples are copied from the application repository. Update documentation when application behavior changes.

Each documentation page is also exported as Markdown; `/llms.txt` lists the guides in all nine languages. Full docs are available at `/docs/llms-full.txt` and under `/docs/<lang>/llms-full.txt` for `zh`, `ja`, `ko`, `fr`, `de`, `es`, `pt` and `ru`.
